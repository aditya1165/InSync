# ASN04: Design Gallery & Live Demo Requirements

**Source:** Instructor document `ASN04_Design_Gallery X Update.pdf`, 2 pages.

**Purpose:** Live peer-reviewed demo, presentation and critique.

**Total:** 80 points: group demonstration 40 + individual review submissions 40.

## Required team-station demonstration
The instructor asks each demo group to:
1. **Motivating scenario:** Present a short, concrete user-problem scenario. Can be a story, storyboard **or** brief live skit; a storyboard/skit is **not individually mandatory**. Make the user need visible.
2. **Problem framing:** State specific problems/user needs and research question or system goal.
3. **Prototype demonstration:** Show prototype/working system and **walk through both interactions**, explaining system and AI behavior.
4. **Implementation progress:** Show **what genuinely works now**, potentially partial UI, features, backend, or code, for both interactions.
5. **Interactive demo:** Allow classmates to try the system and ask questions.
6. **Conciseness:** Explain within a few minutes so visitors have time to interact and score. No exact minute limit is stated.

## Peer-scoring checklist (10 points per project)
| Criterion | Points | Evidence our station should show |
|---|---:|---|
| Motivating scenario clearly shown | 2 | A concrete frontend developer problem, brief story or visual |
| Problem framing / research goal clearly stated | 2 | N1–N3 and task-aware assistant goal |
| Prototype/demo flow clearly shown for **both** interactions | 2 | Complete F3 flow and F4 flow |
| Current implementation progress shown for **both** interactions | 2 | Accurate live vs scripted vs unfinished breakdown |
| Reviewers could interact with system and ask questions | 2 | Working click path, inputs, evidence inspection, team Q&A |

**Group component:** 40 points, determined using peer scores as described in the PDF. Be ready for repeated station demos.

## Individual peer reviews (40 points)
The PDF instructs **every student to review all four demo stations** and submit scores/comments for other teams via a **PDF submission**. For each reviewed project include:
- A 10-point score using the same five 2-point criteria.
- **Two specific strengths**.
- **Two specific weaknesses**.
- Thoughts on the interactions.
- Constructive suggestions for the project's future.

The instructor explicitly warns that vague comments can reduce the individual review grade. Do not score according to personal liking.

## Not specifically required by this ASN04 document
- A storyboard **and** live skit (choose a clear, short motivating scenario format).
- A particular slide count, technology stack, or full production deployment.
- Completion of formal heuristic/cognitive/usability studies as independent ASN04 scoring items.
- Any exact presentation duration, location, or deadline (consult course announcements for these).

## Station-ready checklist
- [ ] A short user story makes the pain point obvious.
- [ ] Problem/goal explained in 1–2 sentences.
- [ ] Interaction 1 runs from selected task through suggested impact to evidence.
- [ ] Interaction 2 runs from Slack/PR link suggestion through decision status to user review.
- [ ] Every AI-looking result is labeled accurately as live/model-generated or scripted.
- [ ] Demo explains current implemented vs incomplete features for **each** interaction.
- [ ] Reviewer can actually interact with the prototype.
- [ ] Demo reset/fallback works repeatedly across visitors.
- [ ] Team can answer design-choice questions.
- [ ] All team members independently prepare peer-review PDF submissions.
